# Cohort executor v2

This package is the separately authorized, still-unexecuted runner and evidence-writer for the frozen Gate-B cohort. It binds contract `f1851be65326365d9bce7b6deb06085f5e0e94d404dcadbdd227df716cb76d9d`, exact roster bytes, the transitive implementation module graph, Node realpath/bytes/runtime, engine records/binaries, and the static executor envelope.

Authorization permits only epoch `execution-epoch:gate-b-v2`, attempt `0`, retries `0`, engine-major serial order Native, Libauth, BCHN, LeanBCH, 4,608 preflight-ready rows per engine, `600000` ms per external logical batch, 128 MiB process capture, concurrency `1`, and no retries/warmups. Lean's two processes share one monotonic 600000 ms budget; its vmbconf aggregate is corroboration only and CostProbe supplies per-item authority. A CostProbe SKIP fails closed and leaves no package. BCHN remains component-only with `tx_checks` unsupported.

The ordinary module and test imports are host-only. No engine or process is touched unless the CLI receives `--execute`, the exact authorization path, and the one authorized absent output path. Native and Libauth execute in the executor process, so the exact command uses the authorization-pinned Node binary under `env -i NODE_ENV=production`; the executor rejects inherited variables. BCHN and Lean child processes receive only their frozen environment maps. Execution stages a complete 27-file container (root plus a nested `attempt-000` holding 25 payloads and its manifest), validates it, atomically renames the whole container, and revalidates it. Any process/parser/validation failure deletes scratch and leaves no partial package.

The frozen raw schema uses `rawObservation.exitCode: 0` for every completed structured observation. For Native and Libauth this is an in-process evaluator/parser completion code, not an OS-process exit status; their invocation endpoint exit code is therefore `null`. The schema-required one-element module `argv` is only the exact module-path locator, not a spawned command; module stdin and stderr are intentionally bound zero-byte streams. BCHN and Lean retain the actual captured external exit code `0` in both places.

`executor.mjs --authorize` regenerates authorization and static package hashes after reviewed source changes. `executor.mjs --check` is read-only and validates authorization, pins, schemas, and the static manifest. The authorization distinguishes the explicit Lean 4.31 build commands/toolchain from the pinned 4.32 host-default preflight diagnostic, which is not build-toolchain proof. The exact execution command is recorded in `COMMAND.txt` and is intentionally not run by this package task.

This component does not qualify BCH transactions, produce rankings or selection, or establish VM evidence until an explicitly authorized future run has passed the full evidence validator.
