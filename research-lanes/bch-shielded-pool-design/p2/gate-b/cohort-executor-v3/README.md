# Cohort executor v3: hardened-validator plus execute-only runner opening

This package is intentionally not an executor. It is a **full-hardened-evidence-validator-static plus non-callable durable runner opening**: it validates a complete, already-captured evidence container against static authority inputs for a future, separately authorized one-use JSON transport at `cohort-execution-authorizations-v3/attempt-001.authorization.v3.json`; that path and the external run base are absent by design.

Before a future runner can act, the validator requires exact v3 contract, inherited v2 epoch/engine/retry/accounting bytes, every static source and schema closure, the current Node runtime and dependency trees, exact frozen entrypoints, serial schedule, 128 MiB per external endpoint cap, and a single 600-second Lean primary-plus-secondary budget. It derives the narrow projection consumed by the accounting package; accounting itself remains non-authoritative.

No default, `--check`, or import path launches a process. The explicit `--execute` branch dynamically opens the descriptor-bound authorization, but is unusable now because the exact external authorization transport is absent. It includes host-tested durable capture primitives, exact codec dispatch, 128 MiB combined external stdout/stderr caps, the shared Lean deadline, claim-before-endpoint ordering, scratch success materialization, and an authenticated Linux `renameat2(RENAME_NOREPLACE)` commit helper. It does **not** yet integrate a retained full authority snapshot, live endpoint orchestration, or sealed failure publisher; those gates fail closed before any endpoint can be reached. The complete 26-payload validator remains read-only: raw transcript spans, normalized projections, all 283,920 metric cells, cross-engine agreement, exact authorization/claim copies, manifest/root joins, and filesystem closure are checked without a BCH VM. No partial results, ranking, selection, or full-pool policy claim is permitted.
